# AdminPage & DashboardPage 測試案例

> 狀態：初始為 [ ]、完成為 [x]
> 注意：狀態只能在測試通過後由流程更新。
> 測試類型：前端元素、功能邏輯、Mock API、驗證權限、UI 回饋

---

## [x] 【前端元素】確認 DashboardPage 的基本資訊渲染
**範例輸入**：以一般用戶身份進入 Dashboard  
**期待輸出**：頁面應顯示「儀表板」標題、用戶名稱（如 Welcome, dean）及身份標籤（一般用戶）。

---

## [x] 【驗證權限】DashboardPage 應根據角色控制管理後台連結
**範例輸入**：1. role 為 admin 進入 2. role 為 user 進入  
**期待輸出**：admin 應能看到「🛠️ 管理後台」連結；user 則不應看到該連結。

---

## [x] 【Mock API】DashboardPage 成功載入商品列表
**範例輸入**：進入 Dashboard 且 API 成功回傳商品資料  
**期待輸出**：頁面應渲染商品格圖，顯示正確的商品名稱（如：機械鍵盤）與售價。

---

## [x] 【UI 回饋】DashboardPage 載入中狀態
**範例輸入**：API 回傳延遲時進入 Dashboard  
**期待輸出**：頁面應顯示「載入商品中...」與 Spinner。

---

## [x] 【UI 回饋】DashboardPage 載入失敗處理
**範例輸入**：API 回傳 500 錯誤  
**期待輸出**：頁面應顯示「無法載入商品資料」或是伺服器回傳的錯誤訊息。

---

## [x] 【功能邏輯】驗證登出功能
**範例輸入**：點擊「登出」按鈕  
**期待輸出**：應呼叫 `logout` 函式，且頁面自動導向至 `/login`。

---

## [x] 【前端元素】確認 AdminPage 的渲染內容
**範例輸入**：以管理員角色進入 AdminPage  
**期待輸出**：頁面應顯示「🛠️ 管理後台」標題，且角色標記為「管理員」。

---

---

## [x] 【驗證權限】AdminPage 的返回連結
**範例輸入**：點擊「← 返回」  
**期待輸出**：頁面應導向至 `/dashboard`。

---

## [x] 【UI 回饋】商品列表為空時的顯示 (Empty State)
**範例輸入**：API 回傳 `products: []`  
**期待輸出**：頁面不應崩潰，且應保持「商品列表」標題存在（或額外顯示無商品提示）。

---

## [x] 【前端元素】驗證金額格式化 (千分位)
**範例輸入**：API 回傳價格為 `25000`  
**期待輸出**：頁面應顯示為 `NT$ 25,000`。

---

## [x] 【Mock API】模擬 401 錯誤觸發自動登出
**範例輸入**：取得商品清單 API 回傳 401 Unauthorized  
**期待輸出**：應用程式應清除 Token 並自動跳轉至 `/login`。

---

## [x] 【前端元素】驗證角色標籤的樣式類別 (CSS Class)
**範例輸入**：角色為 `admin` 與 `user`  
**期待輸出**：`<span>` 標籤應分別帶有 `role-badge admin` 與 `role-badge user` 的 class，以對應不同顏色。
